# 从目标到攻略

用户给一个目标。先拆，再收资料（最难、最重要），最后写攻略。有能练的，做成练习，不要只堆链接。

先读 `kb/README.md`、`kb/sources-official.md`、`kb/sources-community.md`。已有同目标的 `kb/goals/<id>.md` 就打开接着改，不要另起一套。

## 工作流程

```
- [ ] 1. 写清目标（谁、在哪、怎样算做成）
- [ ] 2. 拆成可检查的步骤
- [ ] 3. 收集资料：官方公开 → 驾校指定 → UP/博主
- [ ] 4. 写进知识库
- [ ] 5. 写成攻略（给人看的）
- [ ] 6. 能练的做成练习卡
```

### 1. 写清目标

一句话：人 + 地点/约束 + 完成标准。  
例：北京 C2，科目一一次过（≥90）。

落到 `kb/goals/<id>.md`。

### 2. 拆步骤

每一步要能打勾。分清「硬条件」（约考、考勤）和「学会」。不要抄网上 30 天课表。

### 3. 收集资料（这一步最难，必须做）

对每一步去网上核，不要凭记忆编链接。

**官方公开（先收）**

- 法律、行政法规、部委通知、国标/行标、政府网站原文
- 交管 12123 等官方 App 里的模拟 / 预约
- 能当**唯一依据**

**驾校指定**

- 东方时尚 App 录播和题库这类：约考认，标 `school`，不是国家标准全文

**UP / 博主 / 商业 App（后收）**

- 只用来讲解和口诀
- 必须写清：适合哪一步、哪年的、和官方冲突听谁
- 宁缺毋滥。没打开核过的不写「推荐」

**不要收**

- 网盘「完整题库.zip」
- 把商业 App 题库原文搬进仓库
- 销售/教练真名、聊天截图（隐私）

### 4. 写进知识库

官方 → `kb/sources-official.md`  
社区 → `kb/sources-community.md`  

每条：`name`、`url` 或搜法、`kind`、`trust`、`use`、`checked`（今天日期）。

目标页里用一张表：步骤 → 先看哪份 → 再看哪份。

### 5. 写成攻略

给人看的页面在 `subjects/` 或 `journal/`，口吻是故事，不是「怎么样 / 记下来」。

攻略里写：上场什么样、按什么顺序学、去哪练、依据是哪份官方文件。  
社区口诀可以出现，但旁边能指回官方或 12123。

网站上不要写 Cursor、不要写「本知识库给 AI 用」。

### 6. 练习

自己根据**公开法规**写成判断/选择，放到 `public/practice/<id>.json`，页面用 `<Quiz src="/practice/<id>.json" />`。

字段：`q`、`type`（`tf` | `choice`）、`answer`、`why`、可选 `options`。  
`why` 写法规意思，不写「宝典第 x 题」。  
用户错过的原题：压缩进科目笔记，不进 JSON。

## 对话里怎么回

说清楚：拆成了哪几步、官方收了什么、社区收了什么、攻略和练习在哪。  
整包题库不公开就直说，不要假装已经下载了 2026 全库。
