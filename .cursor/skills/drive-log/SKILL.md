# 记录驾考

用户通常只给一句话。从中判断类型，落到档案、科目笔记、日志三处，不要追问细节。

先读 `system/profile.md` 的 `profile` 区块，再动手。

## 工作流程

```
- [ ] 1. 判断这句话属于哪一类
- [ ] 2. 写或追加 journal/YYYY-MM-DD.md（练车 / 刷题时）
- [ ] 3. 回写对应 subjects/kemuN.md
- [ ] 4. 需要时更新 profile
- [ ] 5. 更新 journal/index.md（第一次写日志时）
```

### 1. 分类

| 用户的话 | 类型 | 落到哪 |
|---|---|---|
| 今天练了 XX / 入库压线 / 坡道熄火 | 练车 | journal + 对应科目失败点 / 口诀 |
| 这题又错了 / 黄灯那题 / 科目一 90 分 | 刷题 | journal（可简）+ kemu1 或 kemu4 易错 |
| 教练说 / 看点是 / 打到底再回半圈 | 口诀 | 对应科目的「教练口诀 / 手感」 |
| 约了科目二 / 科目一过了 | 进度 | `system/profile.md` |
| 我在杭州考 C1，刚开始科目一 | 档案 | `system/profile.md` |

一句话里可以同时有几类，都做。没提日期就用今天。没提科目就按 `profile.current` 推断，并在回复里点一句假设。

**科目映射**

- 倒车入库、侧方停车、坡道、直角、曲线、库 → kemu2
- 灯光、靠边、加减挡、直线行驶、路口语音 → kemu3
- 题库、选项、满分 100、90 过 → kemu1；已过科目一之后的题库默认 kemu4
- 明确说了「科目一/二/三/四」以用户为准

**状态从语气推断**，不要反过来问：

| 用户的话 | mood |
|---|---|
| 一次过 / 稳了 / 手感有了 | 5 |
| 比上次好 / 基本能进 | 4 |
| 还行 / 练了几次 | 3 |
| 压线、扫库、熄火、挂科 | 3，问题写进失败点 |
| 完全没感觉 / 越练越差 | 2 |

### 2. 写日志

路径 `journal/YYYY-MM-DD.md`。当天已有就追加，不要覆盖。

```markdown
---
title: YYYY-MM-DD 周X
date: YYYY-MM-DD
kind: practice
subject: kemu2
items: [倒车入库, 侧方停车]
mood: 3
---

# YYYY-MM-DD 周X

**科目二** · 倒车入库 + 侧方停车

## 怎么样

用户原话的整理，加上一句判断。提到问题就写原因
（比如「右库打晚了」→ 后视镜对上线才打，库角已经贴上）。

## 记下来

- 倒车入库 —— 一句话结论，下次具体怎么改
- 侧方停车 —— 一句话结论
```

`kind`：`practice` 练车 · `quiz` 刷题 · `exam` 上场考试 · `note` 只记口诀没练。
`items` 用项目名或题群名，不要空着。

只改档案、只记口诀、没有「今天练了 / 刷了」时，可以不写日志。

### 3. 回写科目笔记

打开对应的 `subjects/kemuN.md`。原来是 `- _（还没有）_` 的占位，用第一条真实记录替换掉。

**练车失败点**（追加，不要删旧的）：

```markdown
- **YYYY-MM-DD** —— 现象。原因。下次具体怎么改。
```

要可执行：不要写「下次注意点」，要写「右后视镜刚看到库角就回正，比这次早半秒」。

**教练口诀 / 手感**：写成「看哪里 → 做什么 → 做到什么程度」。和已有口诀冲突时，**以用户这次说的为准**，旧的改成「旧：…（已被教练纠正）」。

**易错题**（科目一 / 四）：

```markdown
- **题意一句话** —— 正确答案。你为什么会错。容易和哪题混。
```

同一题已存在就只补原因，不新建条目。

### 4. 更新档案

只在用户明确提到时改 `system/profile.md` 的 frontmatter：

- 过了某科：加入 `passed`，`current` 改下一科
- 约考：`exam_dates.kemuN` 写成 `YYYY-MM-DD`
- 驾校 / 教练 / 城市 / C1 或 C2：写入对应字段；C2 时 `transmission` 改成 `自动`

正文进度清单的勾选和 `passed` 保持一致。

### 5. 更新日志索引

`journal/index.md` 开头若是「> 还没有记录」，第一次写日志时换成最近日志列表；之后每次在列表顶部加一行：

```markdown
- [YYYY-MM-DD 周X](/journal/YYYY-MM-DD) —— 科目二 · 倒车入库 + 侧方停车
```

## 例子

**输入**

> 今天练倒车入库，右库后视镜对上线才打方向，扫到库角了

**三处改动**

1. 新建 `journal/2026-09-03.md`，`subject: kemu2`，`items: [倒车入库]`，`mood: 3`
2. `subjects/kemu2.md` 倒车入库失败点加「右库：后视镜刚对上线就打，再晚会扫库」
3. 若 `profile.current` 仍是 `unknown` 或 `kemu1`，改成 `kemu2`（用户已经在练科目二）

**对话里回复**：一句话确认记好了 + 针对这次失败的一条具体改法。不要复述整篇日志。

## 不要做的事

- 不要追问「打了几圈方向盘」「离合抬到哪」。用户没说就不要编数字。
- 不要用网上的通用场地尺寸覆盖用户或教练给出的看点。
- 不要把整道题库题干抄进笔记。题意压缩成一句。
- 地基信息（城市、C1/C2、当前科目）完全未知时，只问**一个**最有用的问题，不要连珠炮。
